# VirtLite

Лёгкий менеджер виртуальных машин для Mac на Apple Silicon, построенный на нативном
`Virtualization.framework`.

VirtLite запускает Linux-гостей на нативной скорости — без прослойки эмуляции и без тяжёлого
десктоп-комбайна. Выбрать образ, задать ядра и память, запустить. Весь сценарий.

> **Статус: ранняя разработка.** Пользоваться пока нечем. Написано ТЗ и заложен скелет проекта;
> первая веха — Linux-гость, загружающийся с `.iso`. См. [Этапы](#этапы).

**English README:** [README.md](README.md)

## Требования

| | |
|---|---|
| Хост | Mac на Apple Silicon (arm64) |
| macOS | 26.0 или новее |
| Xcode | 26.0 или новее (для сборки из исходников) |

macOS 26 — осознанный минимум. Именно там появились ASIF (разреженный формат образов) и
`VZVmnetNetworkDeviceAttachment`. Компактные диски и проброс портов — это то, ради чего
VirtLite существует, а поддержка более ранних версий означала бы две параллельные ветки кода
в дисковой и сетевой подсистемах на весь срок жизни проекта.

## Что умеет

- Создавать и запускать Linux-VM из локального `.iso` или из проверенного шаблона дистрибутива
- Настраивать ядра, память и диски — с пределами, которые сообщает сам фреймворк
- Выход в интернет через NAT и проброс TCP/UDP-портов внутрь гостя
- Общие папки с хостом и общий буфер обмена там, где гость это поддерживает
- Запуск x86_64-бинарников Linux внутри ARM-гостя через Rosetta
- Сохранение и восстановление состояния машины
- Экспорт, импорт и клонирование VM-бандлов

## Чего не умеет

Это постоянные ограничения платформы, а не пробелы, которые кто-то однажды закроет:

- **Windows-гости.** `Virtualization.framework` запускает только Linux и macOS. Продукты,
  которые запускают Windows на Apple Silicon (UTM, Parallels), используют QEMU или собственный
  гипервизор поверх низкоуровневого `Hypervisor.framework`. Поддержка Windows означала бы
  другой продукт.
- **Гостевые x86_64-системы.** Rosetta транслирует отдельные x86_64-бинарники внутри ARM-гостя,
  но не запускает x86_64-операционную систему.
- **Intel Mac в роли хоста.**
- **Bridged networking.** API существует, но требует разрешения `com.apple.vm.networking`,
  которое Apple выдаёт по индивидуальному запросу. Проброс портов закрывает большинство задач,
  ради которых этот режим и нужен.
- **3D-ускорение для Linux-гостей.** Фреймворк даёт Linux экран без аппаратного 3D. Тяжёлые
  рабочие столы будут медленными, лёгкие окружения — нормально.

## Этапы

| Этап | Объём |
|---|---|
| 0 | Research, entitlements, headless proof of concept |
| 1 | **MVP** — создание, запуск и остановка Linux-VM из `.iso`; CPU/RAM/диск; NAT; список VM и окно экрана |

(`VM-01`, `HW-05`, `NET-02`), на них ссылаются issue и pull request'ы.

## Сборка

```sh
git clone https://github.com/ispy4you/VirtLite.git
cd VirtLite
swift build
swift test
```

Чтобы запустить приложение, соберите подписанный бандл через `Scripts/build-app.sh`. `swift run`
не подойдёт: запуск гостя требует entitlement, а entitlement появляется только из подписи.
Границы слоёв и что куда класть — в [CONTRIBUTING.md](CONTRIBUTING.md).

## Архитектура

Три слоя, граница проходит по жизненному циклу VM:

- **`VirtLiteCore`** — формат бандла, конфигурация, валидация, импорт и экспорт. Импортирует
  только Foundation. Никогда не импортирует `Virtualization` — это проверяет CI.
- **`VirtLiteVZ`** — бэкенд на `Virtualization.framework`, реализующий протокол жизненного цикла.
- **`VirtLite`** — приложение на SwiftUI.

Разделение нужно, чтобы движок тестировался в CI без запуска VM и чтобы CLI позже стоил дёшево.
Кроссплатформенность тут ни при чём: порта под Windows не планируется.
